## 1. 需求梳理

### 1.1 客户背景

- 客户是**第三方服务公司**，不是医院本身。服务对象是几十家到上百家医疗机构（招聘帖写「医院」，字段模板里的科室/设备/人员全是医美场景：皮肤管理区、激光室、强脉冲光治疗仪、美容师，判断主要是**医美类医疗机构**，也可能兼有普通医院）。
- 每家机构有几台到几十台医疗设备，客户帮他们做**设备全生命周期管理**：固定资产建档、采购来源、报废年限、消毒记录、维修保养记录。
- 每家机构需要开 **2～3 个登录账号**，按岗位分权限，可查询、调用本机构设备信息。
- 客户在通话里问「账号不得用我们自己的账号吗」——**是的，草料账号必须用客户公司主体注册**，我方只是被加为管理成员来搭建，交付后数据、账号、续费都在客户手里。

### 1.2 需求清单

### 1.3 资料之间的不一致 / 需确认点

1. **「医院」还是「医美机构」**：字段模板明显是医美（激光/光电设备），招聘帖和通话说医院。方案按医美类医疗机构做，字段对普通医院同样适用；建议向客户确认，涉及巡检项和培训话术。
2. **使用登记每次使用都填 7 个字段**（含客户脱敏信息、能量参数、术后皮肤状态）：对一线美容师负担很重，执行率是这套系统成败的关键。建议把「使用登记」做成**简版必填 + 详版选填**，或者只在光电类设备上启用。
3. **服务客户（姓氏+手机号后 4 位）** 属于个人信息，存在第三方 SaaS 上要提示客户做隐私合规评估；可以改为「客户编号」或干脆不存。
4. **巡检表单**招聘帖提了，但字段模板里没有巡检项，需要客户给检查项清单（或由我方按设备类型给一版默认项）。
5. **机构负责人要不要电脑后台**（看报表、导出 Excel）还是手机扫码能看全信息就行？这直接决定要买多少个高级成员名额（见第 3 节成本）。
6. 现有数据：客户是否已有 Excel 台账，有的话直接整理导入，省一大半录入工作。

## 2. 总体方案设计

### 2.1 账号与组织架构

```
草料组织主账号（客户公司主体注册、客户付费）
│
├─ 组织管理员：客户负责人 1 人 + 我方 1 人（高级成员 · 管理全组织）
│
├─ 分区「XX 医美 A 院」            ← 每家机构一个分区，数据互相隔离
│    ├─ 分区负责人：机构负责人（高级成员·仅查看 / 或普通成员，见 2.4）
│    ├─ 普通成员：护士 / 行政 / 采购（免费、不限人数）
│    └─ 活码：设备 001、设备 002 … （一台设备一个码）
│
├─ 分区「XX 医美 B 院」
│    └─ …
│
└─ 分区「服务商内部」               ← 我方工程师、备用模板、测试码
```

要点：

- **分区 = 机构**。草料高级版起支持分区管理，分区之间数据独立，负责人只能看到自己分区的码和数据，正好对应「每家机构只看自己的设备」。
- **一码一设备**。用草料「批量生码」从 Excel 一次生成一家机构全部设备的活码，静态信息随 Excel 带入，后期可改。
- **码放在分区目录里**，按机构再按科室建目录，方便后台按机构导出。

### 2.2 设备码的内容结构（对应客户的三层模板）

扫码后页面自上而下：

| 页面区块 | 对应客户模板 | 草料实现 | 谁能看 |
| --- | --- | --- | --- |
| ① 设备头卡：照片、通用名称、品牌型号、资产编号、SN、当前状态 | 模块一·设备身份信息 | 活码内容「图文/表格」模块 + 「状态」组件（正常/带病运行/停用/维修中/转让/已报废） | 所有已登录成员 |
| ② 使用与归属 | 模块一·使用与归属信息 | 「表格」模块 | 所有已登录成员 |
| ③ 快捷按钮：使用登记 / 消毒登记 / 报修 | 模块二 + 故障上报 | 表单入口按钮 | 所有已登录成员 |
| ④ 动态履历：使用记录、消毒记录、维修保养记录、巡检记录 | 模块二 | 「记录表单」×4，记录列表挂在码下，自动按时间排列 | 所有已登录成员（填写人只看自己的可另设） |
| ⑤ 采购与资质信息（注册证号、供货商、单价、发票、合同） | 模块一·采购与资质信息 | 「表格」模块，设置**指定成员可见** | 机构负责人 + 服务商 |
| ⑥ 合规文件（13 类扫描件） | 模块三 | 「文件」模块，PDF/图片附件，设置**指定成员可见** | 机构负责人 + 服务商 |
| ⑦ 操作手册 / SOP | 模块三 | 「文件」或「视频」模块 | 所有已登录成员 |

### 2.3 表单设计

草料表单有手写签名、图片、文件上传、日期、定位、检查项、自动带入填表人等组件，客户模板的字段都能落地。

**A. 使用登记（每次使用）** — 建议简版

| 字段 | 组件 | 备注 |
| --- | --- | --- |
| 使用日期 | 日期，默认今天 | 必填 |
| 操作人 | 自动带入填表人姓名 | 必填，不用手输 |
| 客户编号 / 客户脱敏信息 | 单行文本 | 选填，隐私见 1.3 |
| 使用模式 / 能量参数 | 单行文本 | 光电设备必填 |
| 操作时长（分钟） | 数字 | 选填 |
| 术后皮肤状态 | 单选：正常/红肿/异常 | 异常时显示「拍照」（条件显示） |
| 设备运行是否正常 | 单选：正常/报错 | 报错时显示「描述」+ 自动通知工程师 |

**B. 消毒记录（每次消毒）**

| 字段 | 组件 |
| --- | --- |
| 消毒日期时间 | 日期时间，默认当前 |
| 消毒方式 | 单选/多选：75% 酒精擦拭 / 紫外线 / 其他 |
| 消毒耗材批号 | 单行文本（可开「自动带入上次内容」） |
| 执行人 | 自动带入填表人 |
| 执行人签名 | 手写签名 |

**C. 维修保养记录（每次发生）**

| 字段 | 组件 |
| --- | --- |
| 记录类型 | 单选：预防性保养 / 故障维修 / 年度校准 / 耗材更换 |
| 发生日期 | 日期 |
| 故障现象描述 | 多行文本（记录类型=故障维修时必填） |
| 维修/保养内容 | 多行文本 |
| 更换配件名称型号 / 批次号 | 单行文本 ×2（条件显示） |
| 维修厂商 / 人员 | 单行文本 |
| 维修费用（元） | 数字 |
| 验收结果 | 单选：合格/不合格 + 验收人手写签名 |
| 本次维修质保期至 | 日期 |
| 校准报告编号 / 校准有效期 | 文本 + 日期（记录类型=年度校准时必填） |
| 现场照片 / 维修单 | 图片、附件 |

**D. 巡检表单（按计划周期）** — 检查项待客户确认，默认版：

外观完好 / 电源线插头 / 指示灯与显示 / 报警功能 / 手柄与配件齐全 / 冷却或耗材余量 / 环境温湿度 / 清洁消毒到位 / 异常拍照 / 巡检人签名。配合草料「计划管理」设周巡检/月巡检任务，超期自动提醒负责人。

**E. 故障上报表单（随时）**

| 字段 | 组件 |
| --- | --- |
| 故障现象 | 单选（常见故障）+ 多行文本 |
| 严重程度 | 单选：停机 / 影响使用 / 轻微 |
| 现场照片 / 视频 | 图片 |
| 上报人 & 电话 | 自动带入 |
| 处理进度标签 | 待处理 → 处理中 → 已解决（服务商工程师改） |

提交后通过草料「消息提醒」推送到服务商工程师和机构负责人的微信，形成报修闭环，并把该设备状态改为「维修中」。

### 2.4 权限设计（对应客户「权属分类」）

| 角色 | 草料成员类型 | 能做什么 | 数量与成本 |
| --- | --- | --- | --- |
| 服务商管理员（我方 + 客户总部） | 高级成员 · 管理全组织 | 建码、改模板、批量导入、看全部机构数据、导出、改权限 | 2～4 人，用旗舰版自带名额 |
| 服务商维修工程师 | 高级成员 · 管理指定分区（可管理） | 接收报修通知、填维修记录、改设备状态、改处理进度 | 按人数，自带名额内 |
| 机构负责人 | **方案甲**：高级成员 · 本分区负责人（仅查看）——可登录后台看本机构报表、导出 Excel<br>**方案乙**：普通成员 + 敏感模块「指定成员可见」——手机扫码看全信息，不进后台 | 甲：每人 ¥96/年（超出 20 人后）<br>乙：免费 |
| 临床护士 / 行政 / 采购 | 普通成员（免费、不限量） | 扫码看①②④⑦，填使用/消毒/巡检/报修 | 免费 |
| 外部维修厂商 | 普通成员或不给账号 | 由服务商代填维修记录 | 免费 |

所有码的查看权限设为**「仅组织成员可见」**（扫码需微信登录），避免外人扫码看到设备信息；敏感区块⑤⑥再叠加「指定成员可见」。**方案乙里普通成员能否被选为「指定可见成员」，以及跨机构普通成员能否互相看到码，要在试点阶段实测，不行就切方案甲。**

### 2.5 到期提醒

需要提醒的日期：注册证有效期、质保截止日、校准有效期、预估报废日、维修质保期。

- 优先用草料的计划/提醒功能（年度校准建成周期计划）。
- 草料对静态日期字段的到期提醒若受版本限制，则纳入每周维护：导出台账 → 筛选 60 天内到期 → 微信通知客户。这一步写进维护 SOP，不额外增加客户成本。

### 2.6 二维码打印张贴

| 项目 | 建议 |
| --- | --- |
| 标签内容 | 机构简称、设备通用名称、资产编号、SN、二维码、一句提示「扫码查档案 / 登记 / 报修」 |
| 尺寸 | 手持/小型设备 40×30 mm；主机/大型设备 60×40 mm 或 70×50 mm |
| 材质 | PVC 合成纸或 PET 哑银，防水、耐 75% 酒精反复擦拭，背胶用强粘 |
| 张贴位置 | 机身铭牌旁、不遮挡散热口和操作面板；每台设备贴 1 张 + 备用 1 张交机构负责人 |
| 出图方式 | 草料「标签排版」按模板批量套版导出 PDF → 打印店或热转印标签机；也可由服务商统一印好按机构分袋寄出 |
| 试打 | 先打 3～5 张试贴一周，看酒精擦拭后是否脱色再批量印 |

### 2.7 数据统计与导出

- 后台按分区（机构）/ 按设备导出台账 Excel 和各类记录 Excel。
- 用草料统计功能做三张看板：设备状态分布、本月消毒/巡检完成率、待处理故障。
- 每月给客户一份「设备管理月报」（维护时间内完成）。

## 4. 实施计划（兼职/远程，约 3 周）

| 阶段 | 内容 | 产出 | 预计工时 |
| --- | --- | --- | --- |
| 第 1 周 · 定版 | 与客户确认第 1.3 节问题；客户注册草料组织并购买版本；把我方加为管理员；选 1 家机构做试点：建分区、建 5 张表单、建设备码模板、导入试点机构设备、配置权限、实测方案乙的可见性 | 试点机构可扫码演示的完整系统 | 8～12 h |

## 6. 30 分钟培训大纲（一线技师）

| 时间 | 内容 |
| --- | --- |
| 0～5 min | 为什么贴码、扫码能看什么（用一台真实设备演示） |

| 20～25 min | 常见问题：扫码要微信登录、没权限怎么办、填错了怎么改 |

## 7. 每周远程维护（2～4 小时）内容与响应约定

- **固定项**：新增机构/设备录入生码、成员增删、漏填/异常记录检查并提醒机构、60 天内到期项清单推送、表单字段按反馈微调。
- **月度项**：设备管理月报（状态分布、消毒/巡检完成率、故障处理时效）。
- **响应约定**：工作日消息 4 小时内响应；影响一线登记的故障（如码打不开、表单提交失败）当天处理；新增需求下次维护窗口处理。
- **边界**：草料平台本身故障、新增大模块（如审批流、对接 ERP）不在周维护内，另行报价。

## 8. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 一线执行率低，记录不完整 | 使用登记做简版；字段能自动带入的全部自动带入；培训后前两周每周看填报率并反馈给机构负责人 |
| 草料版本/名额/可见性设置与预期不符 | 试点周实测，不行切方案甲；费用提前告知客户 |
| 上千台设备数据录入工作量大 | 由客户/机构用采集表填，我方只做校验和导入；录入量大的按机构另计费 |
| 合规文件扫描件多、存储超限 | 扫描件压缩到 300 dpi 以内 PDF；旗舰版 30G 一般够用；超限增购容量 |
| 客户个人信息（服务客户脱敏）合规 | 建议不存或只存客户编号，在方案里明确写出 |
| 平台锁定（数据在草料） | 每月导出全量 Excel 备份存客户本地 |

## 10. 需要客户确认的问题（可直接发给客户）

1. 机构总数、设备总数大概多少？先拿哪一家（或哪几家）做试点？
2. 草料账号用贵公司主体注册，版本建议旗舰版（约 ¥2,680/年，含 20 个高级成员），是否认可？
3. 各机构负责人是需要登录电脑后台看报表/导出，还是手机扫码能看到全部信息即可？（前者每人约 ¥96/年）
4. 「使用登记」是否要求每次使用必填？是否接受简版（日期、操作人、参数、是否正常）？
5. 「服务客户」信息是否一定要记录？建议改为客户编号或不记录。
6. 巡检的频率和检查项清单能否提供？没有的话我按设备类型出默认版。
7. 故障上报后通知谁？维修由贵司工程师上门还是厂商处理？
8. 标签打印由各机构自行打印，还是贵司统一印制后寄送？
9. 是否已有 Excel 台账或纸质档案可以直接整理导入？
10. 培训对象人数、可安排的时间；维护响应时效的要求。
